# ლექტორისთვის · ლექცია 1

ეს გვერდი მხოლოდ ლექტორისთვისაა: გეგმა, რას უნდა მიაღწიო, როგორ ჩაატარო აქტივობები, მაგალითები, მოსალოდნელი კითხვები და დავალებები ამოხსნით. სტუდენტები ამ გვერდს ვერ ხედავენ.

## 🎯 მიზანი

ლექციის ბოლოს სტუდენტმა უნდა:

1. **საკუთარი სიტყვებით ახსნას**, როგორ წერს LLM პასუხს: ტოკენი → შემდეგი ტოკენის ალბათობები → არჩევა → გამეორება.
2. **გაიგოს სამი შედეგი**, რომელიც მთელ კურსზე დაგვჭირდება: ტოკენი = ფული და ლიმიტი; მოდელი წერს სავარაუდოს, არა ჭეშმარიტს (hallucination); მოდელი stateless-ია.
3. **ამოცანის მიხედვით აირჩიოს** Temperature და Max Tokens და წაიკითხოს `finish_reason`.
4. **თავის პროექტში გამოიძახოს** მოდელი `IChatClient`-ით და დაინახოს, რომ პროვაიდერის შეცვლა ერთ ადგილას ხდება.

```warn
მთავარი რისკი ამ ლექციაზე — თეორია გაიწელება და ლაივ კოდს დრო არ დარჩება. ნაწილი 2 (როგორ მუშაობს LLM) **25 წუთზე მეტი არ უნდა იყოს**. ზედმეტი დეტალები (pre-training-ის ეტაპები, Top-P) მოკლედ, კონსპექტზე მიუთითე.
```

## ✅ მომზადება ლექციამდე

ლექციაზე ვიყენებთ **Gemini**-ს. ლექტორს key აუცილებლად სჭირდება; სტუდენტებისთვის key სასურველია (უფასო ლიმიტი საკმარისია; ვისაც მეტი სურს — ფასიან ტარიფზე გადადის), მაგრამ ვისაც არ აქვს, ლექციას მაინც მიჰყვება (იხ. ქვემოთ).

**რამდენიმე დღით ადრე** — სტუდენტებს გაუგზავნე:

```text
შემდეგ ლექციაზე (AI მოდულის დასაწყისი) Gemini-ს გამოვიძახებთ ჩვენი API-დან.
თუ გინდათ, რომ კლასში თქვენც გაუშვათ:
1. https://aistudio.google.com → Get API key → Create API key (უფასო ლიმიტით)
2. Windows ტერმინალში: setx GEMINI_API_KEY "თქვენი key"
3. Visual Studio გადატვირთეთ
key არავის გაუზიაროთ და კოდში/GitHub-ზე არ ჩაწეროთ.
```

**ლექციის დღეს, შენს კომპიუტერზე:**

- ☐ `GEMINI_API_KEY` დაყენებულია და Visual Studio **ამის შემდეგ** გაიხსნა
- ☐ მოდელის სახელი (`gemini-3.8-flash`) [სიაში](https://ai.google.dev/gemini-api/docs/models) ისევ არსებობს — თუ შეიცვალა, სლაიდებშიც და კოდშიც ახალი ჩაწერე
- ☐ RestaurantApi იხსნება და Swagger მუშაობს; NuGet-ები (`Microsoft.Extensions.AI`, `Google.GenAI`) ჯერ **არ** არის დაყენებული — კლასში აყენებ
- ☐ ბრაუზერში ღიაა [tiktokenizer.vercel.app](https://tiktokenizer.vercel.app) (თამაში 1)
- ☐ ოთხივე ექსპერიმენტი ერთხელ გაიარე სახლში — იცოდე, რას დაინახავენ (განსაკუთრებით ექსპერიმენტი 2: Gemini-ზე ტექსტი შეიძლება ცარიელი დაბრუნდეს)
- ☐ დაფაზე ან ჩატში სტუდენტების პასუხების შესაგროვებელი ადგილი (თამაში 2-ისთვის)

**სტუდენტი key-ს გარეშე:** ლაივ კოდს შენს ეკრანზე მიჰყვება და ექსპერიმენტების პროგნოზებში მონაწილეობს; კლასის დავალებას წყვილში აკეთებს (key-იან მეზობელთან) ან კოდს წერს და სახლში უშვებს.

## 1 · რატომ AI · სლაიდები 6–10

**რა უნდა დარჩეთ:** LLM ჩვეულებრივ კოდს არ ცვლის — ის „ესმის“ ადამიანის ენას, C# კი ზუსტად ასრულებს. backend-ისთვის LLM უბრალოდ კიდევ ერთი HTTP API-ა.

**როგორ ჩაატარო:**

- **სლაიდი 7** — ჯერ ხმამაღლა წაიკითხე სამი შეტყობინება. მერე 2 წუთი წყვილებში: „დაწერეთ if/else და endpoint-ის გამოძახება“. ერთ-ორ წყვილს ჰკითხე, რა გამოუვიდათ. ისინი თვითონ მივლენ დასკვნამდე, რომ „მსუბუქი“ ან „ის წითელსოუსიანი“ წესით არ იწერება — მხოლოდ ამის შემდეგ აჩვენე წითელი ბლოკი.
- **სლაიდი 8** — 🙋 კითხვაზე 3 განსხვავება დაფაზე ჩაწერე სტუდენტების სიტყვებით, მერე გახსენი ბარათები და შეადარე.
- **სლაიდი 10** — Request აჩვენე, ჰკითხე: „რას დააბრუნებს?“ ისინი API კურსიდან იციან, რომ JSON. ხაზი გაუსვი `usage`-ს: „ამაში ვიხდით ფულს — ნახევარი ლექცია ამაზეა“.

**მაგალითები, რაც კარგად მუშაობს:**

- „Google Translate-ის წესები ვინმემ ხელით დაწერა?“ — ML-ის იდეის ასახსნელად.
- კალკულატორი vs ადამიანი: კალკულატორი ყოველთვის ზუსტია, ადამიანს ესმის „დაახლოებით რამდენი იქნება?“ — დეტერმინისტული vs ალბათური.

**მოსალოდნელი კითხვები:**

```check
? „ChatGPT ხომ იგივეა, რაც LLM?“
= ChatGPT **აპლიკაციაა**, რომელიც LLM-ს (GPT მოდელს) იყენებს და ზედ ამატებს ისტორიას, ფაილებს, ძებნას. ჩვენ ზუსტად ასეთ აპლიკაციას ვაწყობთ, ოღონდ რესტორნისთვის.
? „AI ჩაგვანაცვლებს დეველოპერებს?“
= მოკლე პასუხი და დაბრუნება თემაზე: AI-ს სისტემაში ჩაშენება სწორედ დეველოპერის საქმეა — ფასი, უსაფრთხოება, მონაცემები, ტესტები. ამ კურსის მიზანიც ესაა. დებატებში ნუ ჩაერთვები, დრო არ არის.
? „რატომ არ ვიყენებთ Python-ს? AI ხომ Python-ზეა?“
= მოდელების **შექმნა/წვრთნა** ძირითადად Python-ზეა. ჩვენ მზა მოდელს API-ით ვიძახებთ — ეს ნებისმიერ ენაზე კეთდება, და .NET-ს ამისთვის ოფიციალური ბიბლიოთეკები აქვს (Microsoft.Extensions.AI, Agent Framework).
```

## 2 · როგორ მუშაობს LLM · სლაიდები 11–19

**რა უნდა დარჩეთ:** ტოკენი = ფასის/ლიმიტის ერთეული (ქართული — ძვირი); მოდელი ერთ ტოკენს ირჩევს და იმეორებს; წერს სავარაუდოს და არა ჭეშმარიტს; ყოველი მოთხოვნა ცალკეა.

**თამაში 1 · ტოკენები (სლაიდი 13), ~4 წთ:**

1. ორივე წინადადება წაიკითხე. „ინგლისურისთვის ხელი ასწიეთ: 15-მდე? 15–30? …“ — იგივე ქართულზე.
2. tiktokenizer-ში ჩასვი ორივე (tokenizer: `o200k_base`) და აჩვენე ფერადი დაყოფა.
3. ჰკითხე: „რას ნიშნავს ეს ჩვენი რესტორნისთვის?“ — მიიყვანე ფასამდე, სიჩქარემდე, context-მდე. მხოლოდ მერე გახსენი წითელი ბლოკი.

**თამაში 2 · იყავი LLM (სლაიდი 15–16), ~5 წთ:**

1. ყველამ ფურცელზე ან ჩატში დაწეროს **ერთი** სიტყვა. 10 წამი.
2. 5–6 პასუხი ხმამაღლა წაიკითხე და დაფაზე დაითვალე, რომელი რამდენჯერ მოვიდა — ეს არის განაწილება. მერე გახსენი ზოლები.
3. რაუნდი 2: იგივე, ოღონდ წინ „ვეგეტარიანელი ვარ“. დაინახავენ, რომ პასუხები შეიცვალა → „მოდელი მთელ ტექსტს ხედავს“ → ეს არის prompt engineering-ის (ლექცია 2) საფუძველი.

```tip
თუ ვინმემ უცნაური სიტყვა დაწერა (მაგ. „ბანანი“) — ეს საჩუქარია: „აი, ეს არის მაღალი Temperature“. დაიმახსოვრე და მე-3 ნაწილში დაუბრუნდი.
```

**სლაიდი 17 (hallucination):** ჯერ ჰკითხე „რას უპასუხებს?“. სტუდენტები ხშირად ამბობენ „არ იცის და იტყვის, რომ არ იცის“ — გახსენი პასუხი: დამაჯერებლად მოიგონებს. აქ მკაფიოდ თქვი წესი: **ფასი, მარაგი, ჯავშანი — მოდელის მეხსიერებიდან არასდროს.**

**სლაიდი 18 (stateless):** 🙋 „ChatGPT-ს ახსოვს, მოდელს ახსოვს?“ — უმეტესობა იტყვის „კი“. ეს ყველაზე ხშირი გაუგებრობაა, ამიტომ ამას მე-5 ნაწილში კოდითაც ამოწმებენ (ექსპერიმენტი 3).

**მოსალოდნელი კითხვები:**

```check
? „ტოკენი რატომ არ არის უბრალოდ სიტყვა?“
= სიტყვების ლექსიკონი უსასრულოა (ბრუნვები, შეცდომები, ახალი სიტყვები). ნაჭრებით ნებისმიერი ტექსტი იწერება შეზღუდული „ანბანით“ (ათასობით ნაჭერი). ხშირი სიტყვა ერთ ნაჭრად რჩება, იშვიათი იშლება.
? „რატომ არის ქართული ამდენი ტოკენი?“
= tokenizer იმ ტექსტზე „ისწავლა“, რაც ყველაზე ბევრია ინტერნეტში. ქართული ტექსტი იქ ცოტაა, ამიტომ ქართული ასოების კომბინაციებს ცალკე ნაჭრები იშვიათად აქვთ. ახალ tokenizer-ებთან უკეთესდება, მაგრამ განსხვავება მაინც დიდია.
? „თუ მოდელი მხოლოდ შემდეგ სიტყვას გამოიცნობს, კოდს როგორ წერს / მათემატიკას როგორ ხსნის?“
```
